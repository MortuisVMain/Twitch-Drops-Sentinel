# ADR 001. Поведение кнопки закрытия окна

**Дата:** 2026-11-01. **Статус:** принято.

## Контекст
Крестик, Alt+F4 и кнопка закрытия в интерфейсе прятали окно в трей (`e.Cancel = true`, `Hide()`), подсказка (`ShowBalloonTip`, 1,5 с) часто не показывалась (Focus Assist). Пользователи думали, что программа закрылась, а потом «сама открылась». Текст подсказки был скопирован в четырёх местах.

## Решение
Настройка `close_action`: `ask` (по умолчанию) | `tray` | `exit`. При `ask` первое закрытие показывает `TaskDialog` («Свернуть в трей» / «Выйти полностью» + «Запомнить мой выбор»); закрытие диалога без выбора ничего не делает. Все пути закрытия идут через `HandleCloseRequest()`, подсказка одна (`ShowTrayHint()`, 5 с). Сворачивание кнопкой «свернуть» по-прежнему прячет окно в трей. Выход из трея и `exit` используют один `ExitApplication()`.

Значение хранит оболочка в `data/shell_settings.json` (ключ `close_action`), а не Python-сервис: решение принимается до/без бэкенда, а `window_state.json` пишется по границам окна и не подходит. Интерфейс читает/меняет его сообщениями WebView `GET_CLOSE_ACTION` / `SET_CLOSE_ACTION` → `CLOSE_ACTION`.

## Компромиссы
- Первый запуск после обновления спросит один раз; ранее поведением «всегда в трей» теперь можно управлять.
- Вне WebView (браузерная отладка) переключатель в Настройках неактивен.
- Тексты оболочки остаются русскими (как остальные тексты `MainForm.cs`).

## Последствия
Выбор `exit` останавливает фарм при закрытии окна; это явное решение пользователя, подсказка в диалоге об этом предупреждает.
